1. Qué es el Control Plane

Es una aplicación paralela al sitio LA CAJA. Convive en el mismo deploy:

  • / — sitio de LA CAJA (no forma parte de esta guía)
  • /control-plane — consola de infraestructura
  • /api/control-plane/* — APIs del Control Plane

El Control Plane puede operar en simulación, con Kubernetes real, o en modo híbrido (ambas fuentes a la vez). El dominio no habla directamente con la API de Kubernetes: usa adapters (InfrastructureProvider).

2. Arranque rápido

pnpm install
pnpm dev
# Abrir http://localhost:3000/control-plane
Sin cluster conectado, la simulación funciona sola: clusters, nodos, workloads, topología, scheduler y demo de migración.

3. Navegación de la interfaz

Escritorio

  • Sidebar fija a la izquierda
  • Búsqueda / comandos con ⌘K / Ctrl+K
  • Indicador live en la cabecera

Móvil

  • Menú hamburguesa (drawer)
  • Listados en tarjetas (clusters, nodos, workloads)
  • Botones con área táctil ampliada

Secciones principales:

  • Overview — métricas NOC, topología, feed de eventos
  • Clusters — inventario híbrido + Connect Cluster
  • Nodes / Workloads — inventario con badges de origen
  • Scheduler — decisiones de placement explicables
  • Simulation — laboratorio (migración, fallos, GPU sat)
  • Network / Observability / Security — vistas de dominio

4. Modo simulación

  1. Abre /control-plane
  2. Revisa el badge SIMULATION MODE
  3. En Overview pulsa Run migration demo
  4. Observa el feed de eventos y el cambio de nodos/workloads
  5. En Simulation Lab puedes inyectar saturación GPU o resetear el escenario

Los datos simulados están etiquetados como SIMULATED y nunca se mezclan en silencio con datos reales.

5. Conectar un cluster Kubernetes real

5.1 Preparar el cluster local

# kind
kind create cluster --name lab-k8s
kubectl get nodes

# o k3d
k3d cluster create lab-k8s

# exportar kubeconfig
kubectl config view --minify --raw > /tmp/lab-k8s.kubeconfig

5.2 Wizard Connect Cluster

  1. Ve a /control-plane/clusters → Connect Cluster
  2. Name — p. ej. lab-k8s
  3. Provider — Kubernetes (K3s listo; KubeEdge próximamente)
  4. Connection — pega el kubeconfig (solo server-side)
  5. Test — comprueba acceso a la API
  6. Discover — inventaría nodos y workloads
  7. Confirm — resumen Connected / version / nodes
El kubeconfig no se guarda en localStorage ni se reexpone al navegador. Permanece en disco server-side bajo data/control-plane/secrets/ (gitignored).

6. Nodos, workloads y scheduler

  • Nodes — nodos REAL muestran CPU allocatable, RAM, arch, OS, pods
  • Workloads — Deployments reales con namespace, restarts, estado
  • Scheduler — recomienda nodo (score + “Why this node?”) sin reemplazar el scheduler interno de Kubernetes

Filtros en Clusters: ALL · REAL · SIMULATION

7. Desplegar un workload real

  1. Abre el detalle de un cluster REAL
  2. Crea un workload (nombre, imagen, CPU/RAM, placement)
  3. El scheduler propone un nodo
  4. El adapter genera un Deployment en Kubernetes
  5. Sigue el estado: Pending → Running (y eventos)
  6. Desde el detalle: Restart / Stop / Delete
Ejemplo conceptual de WorkloadSpec 
name: traffic-demo
type: edge-application
image: nginx:1.27-alpine
resources: { cpu: 0.2, memory: 128Mi }
placement: { region: lab }

8. Badges REAL / SIMULATED

  • REAL — proviene de un adapter conectado (Kubernetes/K3s)
  • SIMULATED — laboratorio / Digital Twin simulado
  • DISCONNECTED — cluster registrado pero API inalcanzable (último estado conocido etiquetado)

9. Seguridad y buenas prácticas

  • No pegues tokens en chats ni issues
  • No expongas kubeconfig en el frontend
  • Usa cuentas con permisos mínimos para demos
  • La telemetría avanzada (Prometheus) aparece como Not configured hasta conectar un exporter

10. Problemas frecuentes

Connection failed

Unable to reach Kubernetes API → comprueba que el API server es alcanzable desde el proceso Next.js, el contexto del kubeconfig y los certificados.

Solo veo SIMULATED

Aún no hay clusters conectados, o el filtro está en SIMULATION. Usa Connect Cluster.

CPU % en nodos reales

Sin metrics-server/Prometheus, el Control Plane muestra capacidad allocatable, no % live inventado.
